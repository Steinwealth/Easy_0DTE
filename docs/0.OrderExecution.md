```text
Discovery (ORB1 / ORB2 / Trendline)
  → one live chain
  → Trade Profile pick_contract (strike, bid, ask)
  → accept
  → Order Execution sends that strike
  → Demo sim ledger  or  Live E*TRADE order
  → enroll
  → Position Monitoring
  → Profit Capture exit
```

Trade Profile does not place the order. It records the contract on `po_decision_freeze.single_tp.pick`. The executor places that contract.

| **Speed** | No second chain fetch and no retry sleep when the pick is already in hand |

## 1. Speed

The order attempt starts from the contract Trade Profile just accepted. These waits are not on that path:

| Wait | Accept path |
|------|-------------|
| Chain fetch of up to 5 attempts, with 0.25s or 0.5s sleeps | Only when there is **no** Trade Profile pick |
| Estimated-strike walk (`_strike_for_side`) | Only when the hint has no live strike and is not a Trade Profile pick |
| ORB `select_lotto_strike` / `select_single_leg_contract` | Only when `execution_pick` returns nothing |
| Broker chain refresh before submit | Skipped when the selected contract already has a bid and an ask |

What still takes time, and is the intended live fill:

| Step | Bound |
|------|--------|
| In-memory cache align (`peek_cached_options_chain` / the chain already on the ORB signal) | No broker round trip |
| Live limit at the ask, then one lift | `place_single_option_buy_open_smart`. Poll about **0.35s**, about **1s** per attempt, ladder cap **4s** (`max_total_ladder_sec`) |
| Fill reconcile | `EXEC_ENTRY_FILL_RECONCILE_TIMEOUT_SEC` default **4s** |
| Demo sim fill | Same turn. `submit_ts` and `fill_ts` are the same instant |

Discovery, the chain stamp, and the Trade Profile decision are upstream. Their speed is owned by the path guides and [0.TradeProfiles.md](0.TradeProfiles.md). This file starts at **accept**.

## 2. Demo and Live

Both modes read the live E*TRADE chain. `broker_execution_enabled()` in `modules/runtime_mode.py` is true only when `MODE=live`.

| | Demo | Live |
|--|------|------|
| Chain and strike | Live broker chain. `pick_contract` | Same |
| Submit | Blocked. `demo_mode_broker_submit_blocked` if a submit is attempted | `ETradeBrokerAdapter.submit_option_order` |
| Fill price | Ask, via `from_option_contract(..., side="entry")` | Broker `average_fill_price`. If the broker omits it, the ask that was sent |
| Ledger | `MockOptionsExecutor`. GCS `mock_options_history.json` | Broker portfolio. GCS `live_options_history.json` |
| Trade id | `D-…` | `L-…` |
| Metadata | `fill_path=demo_simulated_ledger`, `order_type=DEMO_SIM` | `fill_path=live_broker_confirmed` |
| After the fill | `enqueue_0dte_pending_monitor` → [PositionMonitoring.md](PositionMonitoring.md) | Same enroll. Live also syncs the broker portfolio on the monitor tick |

Demo is the sim of a buy-to-open at the ask on the live contract. The live ladder may pay up to the price margin above that ask if the quote ticks. The sim does not add that lift unless the chain already showed the newer ask inside the margin.

**Settlement (both books):** `(exit − entry) × contracts × 100 − contracts × $1.30`. Open fee $0.65 per contract, close fee $0.65 per contract. Functions: `net_result_pnl_dollars` and `net_result_pnl_fraction` in `modules/options_trade_economics.py`. The headline percent is that settlement divided by premium plus the opening fee.

`ETRADE_MODE` is retired. `MODE` is the switch. Startup rejects a leftover key that disagrees with `MODE`.

## 3. Strike and price

`pick_contract` keeps the nearest out-of-the-money listed contract on the live chain: smallest OTM, then higher absolute delta. It already required a real bid and ask, the delta band (about **0.18–0.42**, from `executor_delta_band`), the OTM cap, premium about **$0.03–$2.50**, volume, open interest, and `spread_check`. The pick stored on the freeze includes strike, delta, bid, ask, spread, volume, and open interest.

`execution_pick` reads `po_decision_freeze.single_tp.pick`. Trendline and ORB2 keep that freeze on `signal.metadata`. ORB1 keeps it on `signal.orb_signal`. A pick is usable when `feasible` is true and strike, bid, and ask are all positive.

`align_pick_to_chain` then sets the order quote:

| Chain at order time | Order |
|---------------------|--------|
| Same strike, ask moved inside the price margin | That newer bid and ask. Log `align=same_strike_quote` |
| Same strike, ask moved past the margin | Original bid and ask, same strike. Log `align=same_strike_held_quote` |
| Exact strike missing, nearest listed strike within **$1**, and that ask is inside the price margin | That neighbor. Log `align=nearest_listed` and `strike_shift` |
| Anything wider | Original strike and ask. Log `align=pick` |

Price margin is `price_margin(ask)`: `max($0.05, min($0.15, 10% of ask))`.

| Selected ask | Margin | Order will chase up to |
|--------------|--------|------------------------|
| $0.45 | $0.05 | $0.50 |
| $1.00 | $0.10 | $1.10 |
| $2.00 | $0.15 | $2.15 |

A Trade Profile pick does not go through the executor delta-band swap. `select_contract` leaves that strike in place (`locked_pick`). `_listed_strike_for_execution` does not snap it onto a different grid strike.

Breakout does not run a second OTM gate on a `selected_by=single_tp` hint. The Trade Profile OTM check already ran.

## 4. Steps

### 4.1 Accept

`single_tp_decide` in `easy0DTE/modules/quality_gate_stack.py` calls `pick_contract`, stamps the decision, and stores the pick on `ctx.extras["po_decision_freeze"]`. `evaluate_chain_skew_from_row` copies that freeze onto the row. The path gate copies it onto the signal:

| Path | Stamp |
|------|--------|
| Trendline | `confirm_trendline_dir_pct_before_execution` → `_stamp_layer_c_on_signal` |
| ORB2 Breakout | `easyBreakout/breakout_pc_oi_gate.py` `_stamp_layer_c_on_signal` |
| ORB1 | `modules/orb1_0dte_watch.py` copies `po_decision_freeze` onto `orb_signal` |

A reject or a defer stops here. No order.

### 4.2 Hand off

| Path | Call |
|------|------|
| Trendline | `modules/prime_trading_system.py` → `trendline_options_executor.execute` |
| ORB2 Breakout | `modules/breakout_watch.py` → `breakout_options_executor.execute` |
| ORB1 | `modules/prime_trading_system.py` 0DTE execution block, route `single_tp_pick` when the pick is present |

Slot cash, the sacred buffer, and the open-position cap run before `execute`. They can refuse the order. They do not choose a different strike. Sizing detail stays in [0DTERisk.md](0DTERisk.md).

### 4.3 Build the order contract

**Trendline and ORB2** share `TrendlineOptionsExecutor._resolve_chain_hint`. With a pick, it builds `chain_hint_from_pick`, peeks the in-memory chain, and `align_pick_to_chain`. Source is `single_tp_pick`. No `_fetch_live_chain_hint`.

`BreakoutOptionsExecutor._resolve_chain_hint` calls that parent, then returns the hint unchanged when `selected_by=single_tp`.

`select_contract` keeps the hint strike and the hint ask (buy to open). Liquidity still runs through `validate_option_entry_liquidity` on that quote (bid, ask, volume, open interest, spread). A failure rejects this candidate. It does not pick a different strike.

`_execute_unified_lotto_open` requires a positive bid and ask (`missing_live_bid_ask` otherwise) and builds `OptionContract` at `_listed_strike_for_execution`.

**ORB1** calls `align_pick_to_chain` on the chain already loaded for that signal. The matching `OptionContract` is the order. When the align says to hold the selected quote, bid and ask are copied onto a new contract so the cached chain row is not overwritten. When no listed leg qualifies, a contract is built from the pick itself. `select_lotto_strike` is not called.

### 4.4 Submit

`OptionsTradingExecutor.execute_lotto_sleeve`:

1. Unified risk (`Unified0DTEPortfolioRiskManager.evaluate_entry`) may reduce size. It does not change the strike.
2. `refresh_contract_quotes_if_enabled` may reuse a warm chain or the manager cache when that cache is within `LIVE_QUOTE_REFRESH_CACHE_MAX_AGE_SEC` (default **5s**) and the matched leg is complete. If the contract already has a bid and an ask, it does **not** call the broker for another chain. Log `LIVE_ENTRY_QUOTE_REFRESH | action=use_selected`.
3. `seal_selected_contract_before_order`.
4. **Demo:** `mock_executor.execute_lotto_sleeve`. Fill price `from_option_contract(contract, side="entry")`, which is `long_option_buy_to_open_price` (the ask). Log text is BTO @ ask.
5. **Live:** `OptionOrderRequest` with that bid, ask, and mid. `submit_option_order` → `place_single_option_buy_open_smart`.

Live limits, in order:

1. The ask.
2. The ask plus `pay_up`, where `pay_up` is the same $0.05–$0.15 margin.

The fill stored is `broker_result.average_fill_price`. A missing broker price falls back to the ask, then the mid, and the ask fallback is logged `LIVE_ENTRY_FILL_PRICE | source=ask`.

### 4.5 Enroll

A confirmed fill is registered for the monitor. The next guide is [PositionMonitoring.md](PositionMonitoring.md). Exits are [0DTEProfitCapture.md](0DTEProfitCapture.md). Exit marks are the executable bid (sell to close), not this entry ask.

These remain in the tree. They run only when the Trade Profile pick is missing, or they are unused by this open.

| Code | When it runs | Why it is not the accept path |
|------|----------------|--------------------------------|
| `_fetch_live_chain_hint` and the retry sleeps | `_resolve_chain_hint` when `execution_pick` is empty | A second selection and a wait |
| `_fetch_degraded_chain_hint` | Same, after the live retries fail | Different contract than the one Trade Profile scored |
| `_strike_for_side` estimated walk inside `select_contract` | No live strike on the hint, and the hint is not a Trade Profile pick | Invented strike, then the hint's bid/ask can belong to a different strike |
| `select_lotto_strike`, `select_single_leg_contract`, `select_opening_preservation_contract` | ORB1 block when `execution_pick` returns nothing | A different selector (`target_delta` around 0.15) |

| Breakout `_stamp_otm_on_hint` | Hints that are not `selected_by=single_tp` | Would reject or restamp a contract Trade Profile already accepted |
| `TRENDLINE_ALLOW_SYNTHETIC_ENTRY` | Default **false** | A synthetic contract is not a live chain fill |

## 10. What “correct” means

1. An accept orders the strike Trade Profile selected from the live chain.
2. The ask may be the newer quote on that strike when the move is inside $0.05–$0.15. A larger move keeps the selected ask.
3. A missing strike may move one listed strike, and only within $1, and only when that ask is inside the same margin.
4. Demo writes that ask onto the sim ledger and does not call the broker.
5. Live sends that ask to E*TRADE, then one lift inside the margin, and records the broker fill.
6. The open position is monitored and exited by [PositionMonitoring.md](PositionMonitoring.md) and [0DTEProfitCapture.md](0DTEProfitCapture.md).
